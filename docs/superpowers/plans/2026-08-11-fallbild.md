# Das Fallbild — Umsetzungsplan

> **Für agentische Bearbeiter:** Umsetzung Aufgabe für Aufgabe, Schritte als Checkboxen.

**Ziel:** Auf `/cases/[id]` steht der Kunde in der Mitte, die fünf Tore des Wegs
zur Einreichung liegen auf einem offenen Bogen darum, die vier nebenläufigen
Fachbereiche in der Mitte. Alles ohne Scrollen, jedes Element anklickbar, dazu
die Empfehlung im Band darunter.

**Architektur:** Eine reine Funktion `baueFallbild` erzeugt aus vorhandenen
Cockpit-Daten ein Anzeigemodell (5 Tore, 4 Felder, Empfehlung). Eine
Client-Komponente zeichnet es als SVG mit `viewBox` — dadurch skaliert das Bild
und läuft nie über. Ein Klick tauscht nur das Band aus, nicht die Seite.

**Technik:** Next.js App Router, SVG (kein Diagramm-Paket), TONE-Farbsystem, vitest.

Spec: `docs/superpowers/specs/2026-08-11-fallbild-design.md`

## Globale Vorgaben

- Es wird **nichts neu gerechnet**: alle Werte stammen aus `cockpit.ts`,
  `next-step.ts`, `ladeErstkontaktStand` und dem Machbarkeits-`Urteil`.
- Fehlt ein Wert, steht dort „noch nicht berechnet" — nie 0 und nie „–".
- „Gesperrt" ist ein Merkmal, kein Zustand: gestrichelt nur bei Fortschritt 0.
- Die Marke „als Nächstes" erscheint nur, wenn der Schritt zuordenbar ist.
- Fachsprache im Code ist Deutsch (Konvention in `src/lib/cases/`).

### Aufgabe 1: Machbarkeits-Urteil im Cockpit behalten

**Dateien:** Modify `src/lib/cases/cockpit.ts`

Heute rechnet der Block `machbarkeitBlockiert` das vollständige `Urteil` aus und
behält davon nur `!machbar`. Künftig wird das Urteil in einer lokalen Variablen
festgehalten und als `machbarkeit` mit ausgegeben:

```ts
machbarkeit: { auslauf: number; band: Auslaufband; ueberschuss: number; machbar: boolean } | null;
```

`null` heißt: Die Daten reichten nicht. `counts.machbarkeitBlockiert` bleibt
unverändert — `next-step.ts` hängt daran.

- [ ] Feld in `CockpitData` ergänzen, Block umbauen, `npm run typecheck`.

### Aufgabe 2: Anzeigemodell und `baueFallbild`

**Dateien:** Create `src/lib/cases/fallbild.ts`; Test `tests/fallbild.test.ts`

**Produziert:**
```ts
export const TOR_IDS = ["erstkontakt","kundendaten","unterlagen","pruefung","einreichung"] as const;
export const FELD_IDS = ["objekt","einkommen","machbarkeit","nachrichten"] as const;

export interface Tor {
  id: TorId; name: string; zustand: string; anteil: number; ton: Tone;
  /** Gesetzt heisst gesperrt; `anteil === 0` entscheidet über die Strichelung. */
  gesperrt?: string;
  detail: string; ziel: { label: string; href: string };
}
export interface Feld {
  id: FeldId; name: string; wert: string; zeile: string; ton: Tone;
  detail: string; ziel: { label: string; href: string };
}
export interface Fallbild {
  fall: { nummer: string; name: string; vorhaben: string; betrag: string };
  tore: Tor[]; felder: Feld[];
  naechstes: { markiert: TorId | FeldId | null; titel: string; grund: string; ton: Tone; ziel?: { label: string; href: string } };
}
export function baueFallbild(e: FallbildEingabe): Fallbild
```

`FallbildEingabe` bündelt: `cockpit` (Ausschnitt), `schritt` (Ergebnis von
`computeNextStep`), `erstkontakt`, `objekt` (Wohnfläche + ob eine freigegebene
Berechnung existiert), `offeneAnfragen`.

- [ ] Test: immer 5 Tore in fester Reihenfolge, immer 4 Felder.
- [ ] Test: kritischer Hinweis sperrt die Einreichung, Grund nennt ihn.
- [ ] Test: ohne Blocker keine Sperre.
- [ ] Test: Prüfung nur bei null Dokumenten gesperrt.
- [ ] Test: gesperrt mit Fortschritt > 0 behält `anteil` (keine Strichelung).
- [ ] Test: `anteil` immer zwischen 0 und 100.
- [ ] Test: `machbarkeit: null` → Felder zeigen „noch nicht berechnet".
- [ ] Test: `schritt.key = "dokumente_freigeben"` markiert `pruefung`;
      `"machbarkeit"` markiert das Feld; `"fristen"` markiert **nichts**.
- [ ] Rot → umsetzen → grün. Commit.

### Aufgabe 3: Die Zeichnung

**Dateien:** Create `src/components/case/fallbild.tsx`

Client-Komponente. SVG mit `viewBox="0 0 780 660"`, `preserveAspectRatio="xMidYMid meet"`.
Geometrie: Mittelpunkt (390, 322), Radius 250, Strichstärke 22, Bogen von 210°
über den Scheitel bis 150° (300°, Lücke unten), fünf Segmente zu 60°.
Felder als abgerundete Rechtecke 140×46 an (±142, ±82) um die Nabe (200×104).

- [ ] Tore zeichnen: Spur in `--muted`, Füllung im Ton, gesperrt mit
      `stroke-dasharray` nur bei `anteil === 0`; unsichtbare breite Trefferfläche
      darüber, damit auch neben dem Strich geklickt werden kann.
- [ ] Beschriftung außen mit Ankerlogik nach Winkel; türkise Marke
      „ALS NÄCHSTES" nur bei `naechstes.markiert`.
- [ ] Start- und Zielpunkt an den offenen Enden, Bildunterschrift
      „diese vier laufen nebenher — ohne feste Reihenfolge".
- [ ] Band unter dem Bild: Empfehlung oder gewähltes Element, Knopf als Link,
      „Zur Empfehlung" zurück. Prop `aktionSlot?: React.ReactNode` wird statt des
      Knopfs gezeigt, wenn die Empfehlung sichtbar ist (KI läuft / KI-Fehler /
      Erstkontakt vorbereiten).
- [ ] Bedienbarkeit: `role="button"`, `tabIndex`, Enter und Leertaste,
      sichtbarer Fokus, `aria-label` je Element.
- [ ] `npm run typecheck`. Commit.
